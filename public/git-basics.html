01

What is Git?

Git is a distributed version-control system. It records changes to project files so you can inspect earlier versions, work safely on new ideas and understand how a project evolved.

Track every change

Git stores snapshots of your project instead of replacing your previous work.

Recover safely

You can compare versions and return to a known working state when needed.

Prepare for teamwork

The same history later supports branches, pull requests, reviews and merges.

02

Set up Git

Before your first mission, install Git and configure the identity that will be attached to every commit.

Install and verify Git

Ubuntu / Debian
$ sudo apt update
$ sudo apt install git
$ git --version
✓ git version 2.43.0

Configure your identity

Your name and email make every commit traceable. You normally configure them once for your computer.

Terminal
$ git config --global user.name "Your Name"
$ git config --global user.email "you@example.com"
$ git config --list
user.name=Your Name
user.email=you@example.com
03

Create your first repository

A repository is a project folder tracked by Git. The hidden .git directory stores its history and configuration.

git init — initialize the repository

Terminal
$ mkdir portfolio && cd portfolio
$ git init
✓ Initialized empty Git repository in /portfolio/.git/
বাংলা সহায়তা

fatal: not a git repository দেখালে বর্তমান folder-টি এখনও Git repository নয়। প্রথমে git init চালান।

Your first meaningful commit

GitStack teaches a professional two-step habit: stage the exact files you want, then commit them with a message that explains the change.

Terminal
# Create the project file
$ echo "# My Portfolio" > README.md
# Stage and commit it
$ git add README.md
$ git commit -m "Add portfolio README"
✓ [main (root-commit)] Add portfolio README
Weakgit commit -m "update"

The change is unclear.

Bettergit commit -m "Add portfolio README"

The message explains what changed.

04

Understand the Git workflow

Every change moves through three areas. Understanding this flow is the foundation for later team collaboration.

1

Working directory

Files you are currently creating and editing.

2

Staging area

Selected changes prepared with git add.

3

Repository

Permanent snapshots saved with git commit.

git status — know where you stand

Terminal
$ git status
On branch main
Changes not staged for commit:
  modified: README.md
Untracked files:
  style.css

git diff — inspect the exact change

Terminal
$ git diff
- # My Portfolio
+ # My Portfolio Website
05

Navigate your history

git log shows commits from newest to oldest. The compact one-line view helps you quickly verify messages and order.

Terminal
$ git log --oneline
c3d4e5f Add contact section
b2c3d4e Add base styles
a1b2c3d Add portfolio README

The .gitignore file

Some files should never enter version control, including dependencies, secrets, operating-system metadata and generated build output.

.gitignore
node_modules/
.env
.DS_Store
*.log
dist/
