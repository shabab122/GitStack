01

How remote repositories work

A remote is another copy of a Git repository hosted on a server. In GitStack team missions, the controlled Gitea repository becomes the shared source of truth while each student works from a separate isolated workspace.

Your isolated workspace

Local files, branches and commits inside your own sandbox.

fetch · pull · push

Gitea team repository

Shared issues, branches, Pull Requests and review activity.

02

Clone the prepared repository

git clone downloads the repository, its history and remote configuration. Git automatically creates a remote called origin.

Terminal
$ git clone https://gitea.gitstack.local/team-alpha/login-project.git
✓ Cloning into login-project...
$ cd login-project
$ git remote -v
origin  https://gitea.gitstack.local/team-alpha/login-project.git (fetch)
origin  https://gitea.gitstack.local/team-alpha/login-project.git (push)
03

Inspect and manage remotes

Use git remote -v to verify where fetch and push operations will connect. GitStack checks that the student workspace points to the assigned team repository.

Terminal
$ git remote -v
$ git remote show origin
HEAD branch: main
Remote branches: main, feature/password-toggle
বাংলা সহায়তা

fatal: remote origin already exists দেখালে নতুন origin যোগ করবেন না। প্রথমে git remote -v দিয়ে existing remote পরীক্ষা করুন।

04

Synchronize with the team repository

git fetch

Downloads remote information without changing your working files.

git pull

Fetches and integrates remote changes into your current branch.

git push

Uploads local commits so teammates and Gitea can see your work.

git fetch — inspect before integrating

Terminal
$ git fetch origin
✓ origin/main updated
$ git log main..origin/main --oneline
f18a2c7 Update login instructions

git pull — update your local branch

Terminal
$ git switch main
$ git pull origin main
✓ Fast-forwarded main to latest remote state

git push — publish a feature branch

Terminal
$ git switch -c feature/password-toggle
$ git push -u origin feature/password-toggle
✓ Branch published and tracking origin/feature/password-toggle

07

Common remote errors

failed to push some refs

The remote contains work you do not have. Fetch or pull the correct branch, resolve any conflict, then push again.

repository not found

Check the assigned Gitea URL and verify that your mapped student account has repository access.

no upstream branch

Use git push -u origin branch-name the first time you publish a new branch.
