01

What is a Git branch?

A branch is an independent line of development. It lets you work on a feature or fix without changing the stable main branch until your work is ready.

main
feature/profile-card

Protect stable work

New code stays isolated until it is tested and ready to merge.

Focus each task

Use one clear branch for one meaningful issue or feature.

Prepare for teamwork

Separate branches make later Pull Requests and reviews easier to understand.

02

Create and switch branches

GitStack accepts different valid commands that produce the required repository state. Both modern git switch and older git checkout syntax can create a branch, but the guide recommends the clearer modern command.

git branch — list and create branches

Terminal
$ git branch feature/profile-card
$ git branch
* main
  feature/profile-card

git switch — move between branches

Terminal
$ git switch feature/profile-card
✓ Switched to branch 'feature/profile-card'

# Create and switch in one command
$ git switch -c feature/profile-image
✓ Switched to a new branch 'feature/profile-image'
বাংলা সহায়তা

fatal: a branch named ... already exists দেখালে branch-টি আগে থেকেই আছে। নতুন করে তৈরি না করে git switch branch-name ব্যবহার করুন।

Make focused commits on the branch

After switching, make only the changes required by the task and use meaningful commit messages.

Terminal
$ touch profile-card.html
$ git add profile-card.html
$ git commit -m "Add profile card structure"
✓ [feature/profile-card a13d8f2] Add profile card structure
03

Merge completed work

When a branch is complete, switch back to main and merge the feature branch. GitStack checks the resulting branch history rather than requiring only one exact command sequence.

Terminal
$ git switch main
$ git merge feature/profile-card
✓ Updating 5e21a91..a13d8f2
✓ Fast-forward
 profile-card.html | 1 +
Before merge

Work remains isolated

The feature branch contains changes that are not yet part of main.

After merge

Main includes the feature

The stable branch now contains the tested profile-card work.

Delete the merged branch

Terminal
$ git branch -d feature/profile-card
✓ Deleted branch feature/profile-card
04

Resolve a controlled merge conflict

A conflict happens when two branches change the same part of a file differently. GitStack’s MVP uses a prepared, deterministic conflict so every student can practise the same workflow.

Terminal
$ git merge feature/profile-theme
CONFLICT (content): Merge conflict in profile.css
Automatic merge failed; fix conflicts and then commit.
profile.css
<<<<<<< HEAD
.profile-card { background: white; }
=======
.profile-card { background: #fff7f1; }
>>>>>>> feature/profile-theme
1

Open the conflicted file

Review both versions and decide what final code is required.

2

Remove conflict markers

Keep the correct functionality and delete the marker lines.

3

Stage and commit

Record the resolved state with a meaningful message.

Terminal
$ git add profile.css
$ git commit -m "Resolve profile theme conflict"
✓ Conflict markers removed
✓ Required styling preserved
✓ Merge commit created
05

Use professional branch names

A branch name should quickly tell teammates what type of work it contains. Use lowercase words, hyphens and a short prefix.

PrefixPurposeExample
feature/New functionalityfeature/profile-card
fix/Correct a defectfix/profile-layout
test/Add or improve teststest/profile-card
docs/Documentation workdocs/branch-guide
Weaknew-work

The purpose is unclear.

How GitStack assesses this level

Branch usage

Commit quality

The commit is focused and its message clearly explains the change.

Merge result

Conflict result
